Lesson 0009

What Makes This Tokenizer Different

What "works without training" actually means, and the five architectural choices that set this tokenizer apart from GPT-2 and Hugging Face.

Step 9 of 13. The algorithm. The five things this repo does that a general-purpose tokenizer does not.

1. What Does "Works Without Training" Mean?

Standard BPE tokenizers (like GPT-2, Llama, Tiktoken, or Hugging Face ByteLevel BPE) start with an initial vocabulary of only 256 raw bytes.

The Untrained Comparison on the word "வணக்கம்" (vanakkam):

In UTF-8, "வணக்கம்" takes 21 raw bytes.

  • Untrained Standard Tokenizer (0 merges):
    Knows nothing about Tamil. Outputs 21 separate byte tokens:
    [<0xE0>, <0xAE>, <0xB5>, <0xE0>, <0xAE>, <0xA3> ... ]
    Without training on millions of Tamil words, it is completely useless.
  • This Tokenizer (0 merges):
    Ships with a pre-compiled base vocabulary of 1,135 Tamil tokens inside vocab.rs.
    Outputs 5 clean syllabic tokens on day zero:
    [வ (517), ண (361), க் (282), க (270), ம் (438)]
The "Zero-Training" Meaning

"Works without training" means the tokenizer can immediately encode and decode grammatically valid Tamil text into meaningful syllabic units right out of the box without running the BPE trainer.

Running the trainer is only needed if you want additional compression (merging those 5 syllables into 1 single word token 974).

2. Five Things This Repo Does Differently

1
1,135 Base Vocab vs. 256 Bytes

Standard tokenizers start with 256 bytes and force the BPE merge budget to spend thousands of steps just rediscovering the Tamil alphabet. This repo pre-seeds all 12 vowels, 23 consonants, and 276 consonant-vowel combinations.

2
528 Pre-Computed Conjunct Stems (23 × 23)

Clusters with a pulli (dot) like ண்ட, த்த, and க்க take 9 bytes in Unicode. Standard tokenizers burn 3 to 4 tokens per cluster. This repo includes all 528 pairs in the base vocabulary, cutting initial token counts across corpora immediately.

3
Indic Unicode Regex (\p{M}*) vs. English Regex

GPT-2 and Llama use regex tailored for English contractions ('s, 't). They often slice Tamil vowel signs away from consonants. This repo's regex groups combining marks (\p{M}*) so vowel signs stay glued to consonants.

4
CSR Layout Merge Table vs. Hash Maps

Standard tokenizers use a large hash map for merge lookups. At 120,000 merges, hash probes blow past CPU hardware caches, dropping speed by 2.4x. This repo uses a bitset filter and a Compressed Sparse Row (CSR) table packed into 64-bit words, keeping lookups inside CPU cache lines.

5
Lossless Byte Fallback vs. <unk> Replacement

Unseen characters, emojis (🔥), and foreign symbols never turn into unknown token tags (<unk>). They decompose into <0xNN> byte tokens and decode back with 100% roundtrip fidelity.
