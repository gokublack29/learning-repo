1. The Two Big Ideas (BPE and Rust)

What is BPE (Byte Pair Encoding)?

Computers and neural networks do not read text directly; they only process numbers (called token IDs).

BPE is a simple compression recipe: start with individual characters or bytes, count which pair of symbols appears together most often in a corpus, merge that pair into one new token, and repeat. Frequent words become a single number, while rare words break into smaller syllables or base bytes.

How Rust Projects Work

In Rust, Cargo.toml is the project manifest (like package.json in Node or pyproject.toml in Python).

Code lives in two kinds of files:

  • Library (lib.rs): Reusable logic shared across the project.
  • Binaries ([[bin]] in Cargo.toml): Standalone programs with a fn main() function that you execute from the command line.

2. The Three Entry Points You Actually Run

This repo has several benchmark and test scripts, but your actual workflow centers on three runnable binaries:

1
Training: train.rs

Learns BPE merge rules from a raw text file and produces a trained JSON vocabulary.

cargo run --release --bin train <corpus.txt> <num_merges> <output.json>
2
Interactive Testing: main.rs

Loads the trained tokenizer JSON and opens a REPL in your terminal so you can type text and see token IDs live.

cargo run --bin main output/tamil_tokenizer.json
3
Single String Encoding: encode.rs

Runs a single sentence through the tokenizer and prints token IDs and reconstructed text.

cargo run --release --bin encode output/tamil_tokenizer.json "வணக்கம்"

3. How Data Flows Through the Repo

Data moves through this codebase in two distinct lifecycles: Training and Inference.

Lifecycle A: Training Flow (Learning the Vocabulary)

A1
Seed Base Vocabulary (vocab.rs)

Initializes 1,135 seed tokens: 256 raw bytes (fallback), independent vowels, consonants, vowel signs, and 528 two-consonant conjunct stems (consonant + pulli + consonant).

A2
Pre-tokenize Corpus (pretokenizer.rs)

Uses regular expressions to split large text files into word chunks across multiple CPU cores via Rayon.

A3
Iterative Merging (trainer.rs)

Packs adjacent token pairs into 64-bit integer keys. In each step, picks the most frequent pair, creates a new token ID, and updates all words.

A4
Save Tokenizer (output/*.json)

Writes the final JSON artifact containing the token-to-ID map and ordered merge list.

Lifecycle B: Inference Flow (Encoding Text)

B1
Input Text String

Raw UTF-8 text string enters encoder.encode(text).

B2
Chunking (pretokenizer.rs)

Regex splits the sentence into words and punctuation boundaries.

B3
Base Mapping & Priority Merging (encoder.rs)

Each chunk becomes base token IDs. The encoder then greedily applies learned merges in priority order (lowest merge rank first).

B4
Output: Vec<u32>

A simple list of 32-bit unsigned integers representing the tokens ready for a language model.
