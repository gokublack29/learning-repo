1. The Five Core Data Types

Rust enforces exact memory sizes. In this repo, you will see five types on almost every line:

Type What it is Where it appears in this repo
u32 Unsigned 32-bit integer (0 to 4.2 billion) Token IDs (TokId). Every token is a u32.
u64 Unsigned 64-bit integer Bit-packed pair keys (packs two u32 IDs into one word).
usize Memory pointer-sized integer Array indexes and lengths (e.g. vec.len()).
String Owned, growable text allocated on the heap Stored token text inside the dictionary (HashMap<String, u32>).
&str A read-only view ("borrow") of text sitting in memory Input arguments like fn encode(&self, text: &str) (avoids copying text).

2. No null and No Exceptions: Option and Result

Rust does not have null or runtime exceptions (like NullPointerException). Instead, it uses two enums:

A. Option<T> (The Safe Null)

A value is either Some(value) or None:

// Looking up a token in a map returns an Option:
let id: Option<&u32> = vocab.get("வணக்கம்");
// If found: Some(&974)
// If missing: None

B. Result<T, E> and the ? Operator

Functions that can fail return Ok(value) on success or Err(error) on failure.

The Magic Question Mark (?):

let data = std::fs::read_to_string(path)?;

The ? at the end means: "If read_to_string succeeds, unwrap the text into data. If it fails, immediately return the Err out of this function." It replaces 10 lines of try/catch boilerplate.

3. Pattern Matching: match and if let

Rust forces you to handle every possible outcome using pattern matching.

A. match (Switch statement with superpowers)

Look at line 13 of main.rs:

let (vocab, merges) = match load_tokenizer(&vocab_file) {
    Ok(v) => v,
    Err(e) => {
        eprintln!("Failed to load vocab: {}", e);
        return;
    }
};

If load_tokenizer succeeds, it extracts (vocab, merges). If it fails, it prints the error and exits.

B. if let (Extract only when present)

Look at line 360 of encoder.rs:

if let Some(id) = sym.id {
    token_ids.push(id);
}

This checks: "If sym.id is Some(id), extract the number into variable id and push it. If it is None, skip it."

4. Structs, Methods, and Borrowing (&self vs &mut self)

In Rust, data (fields) and functions (methods) are defined separately:

// 1. Define the data structure
pub struct OptimizedBPETrainer {
    words: Vec<WordData>,
    pair_freq: HashMap<u64, u32>,
}

// 2. Attach functions to the struct
impl OptimizedBPETrainer {
    // Constructor (Self is an alias for OptimizedBPETrainer)
    pub fn new() -> Self { ... }

    // Read-only method (&self): Can read data, CANNOT modify fields
    pub fn len(&self) -> usize {
        self.words.len()
    }

    // Mutable method (&mut self): Has exclusive permission to MODIFY fields
    pub fn train(&mut self, num_merges: usize) {
        self.words.push(...); // Allowed!
    }
}

5. Iterators and Rayon Multithreading

Instead of manual for loops, Rust uses chainable iterators:

// 1. Standard single-thread iterator:
let ids: Vec<u32> = tokens.iter().map(|t| token_to_id[t]).collect();
// .iter()   -> look at each item
// .map(...) -> transform each item
// .collect() -> assemble results back into a Vec

// 2. Rayon parallel multithreaded iterator:
let batch: Vec<Vec<u32>> = texts.par_iter().map(|t| self.encode(t)).collect();
// .par_iter() splits the work across all available CPU cores automatically!
