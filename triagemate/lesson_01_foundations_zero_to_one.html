If you have never worked in Application Security (AppSec) or trained a code LLM before, start right here. Every single concept in barryallen16/triagemate builds on five foundational ideas.

Architecture Overview: Why Two Packages Coexist (triage/ vs d1_triage/)

The 5 Building Blocks You Must Know Cold

1. Static Analysis (SAST) & Semgrep

Semgrep scans source code without running it by matching AST/syntax patterns (e.g., new File(baseDir, userInput)). Because syntax rules cannot easily prove whether userInput was validated 10 lines earlier, >70% of Semgrep warnings are False Positives (noise).

2. Source → Sanitizer → Sink (Taint Reachability)

An alert is a True Positive (TP) only if untrusted input (Source, e.g. HTTP param) reaches a dangerous API (Sink, e.g. executeQuery()) without an effective guard/check (Sanitizer, e.g. PreparedStatement or Path.normalize().startsWith()).

3. javalang AST Slicing vs. Code Windows

triage/dataset.py uses javalang to parse Java files into an Abstract Syntax Tree and slice only the enclosing method around an alert line. d1_triage/sink_finder.py uses regex sink matching on bounded code windows so it never crashes on uncompilable snippets.

4. Single-Pass Logit Scoring vs. Text Generation

Instead of generating 50 tokens sequentially (~800 ms), TriageMate runs 1 forward pass and reads the next-token logits for positive ("yes", "true", "1") vs. negative ("no", "false", "0") tokens, cutting latency to 12–14 ms and giving a continuous probability P(TP).

Active Recall Check (Test Yourself Before Lesson 2)

Why does TriageMate keep both triage/ and d1_triage/ instead of deleting triage/?

triage/ houses the reusable dataset, AST slicing (javalang), metrics (P@90R, ECE, Within-Rule AUC), remediation hints (explain.py), and Qwen3.5-4B decision scorer wired to the triagemate console script and Dockerfile. d1_triage/ is the standalone sub-15ms inference CLI built specifically for LiquidAI/d1-3B with statement-level sink anchoring.
