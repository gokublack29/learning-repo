Defending Every Design Choice in a Live Interview

Drill 1: "Why wouldn't I just send Semgrep alerts to Claude or GPT-4o instead of using a 3B model?"

Three production reasons: 1) On-premise IP privacy (6.25 GiB VRAM runs locally with zero source code leaving the VPC); 2) CI/CD latency (12–14 ms/alert vs 3–10 s/alert for cloud APIs on thousands of monorepo findings); 3) Two-stage cascade: use d1-3B as the free Tier-1 filter for intra-procedural noise and escalate only the top borderline/high-risk alerts (P(TP) > 0.40) to a heavier multi-file inter-procedural agent.

Drill 2: "Why did Contrastive LoRA get 0.6594 L3 Within-Rule AUC yet drop on Vul4J (0.5444)?"

Training on 416 balanced 50/50 pre-patch (TP) vs post-patch (FP) pairs per rule forces the adapter to attend to subtle sanitizer diffs within a rule (raising L3 Within-Rule AUC from 0.5495 to 0.6594), but erases uneven between-rule base-rate priors. Combining Zero-Shot + Contrastive in the 50/50 Ensemble recovers 0.8000 Vul4J AUC while keeping 0.6280 L3 Within-Rule AUC.

Drill 3: "How did you verify that >>> [ALERT LINE n] actually made the model inspect Java code?"

Via Paired Rule-Swap Controls (Commit f25eac6): swapping code windows between alerts that share the exact same Semgrep rule header caused AUC to drop sharply (Code Signal Delta +0.0749 on L0 Targeted Prompt, +0.0839 on L0 Contrastive, +0.1106 on L3), proving causal dependence on the Java dataflow inside the window.
